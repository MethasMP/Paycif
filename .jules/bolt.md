## 2026-10-28 - ASCII Byte Lookup Table & Incremental Indexing for String Loop Optimizations
**Learning:** In Go, `for i, char := range str` decodes UTF-8 runes which adds CPU overhead. For ASCII string processing (such as ICAO 9303 MRZ strings), using direct byte indexing (`str[i]`), a precomputed 256-element array `[256]int` for character value mapping, and an incremental index counter instead of modulo arithmetic (`i % N`) inside hot loops provides a ~2.34x speedup (63.84 ns/op down to 27.26 ns/op) with zero allocations.
**Action:** When iterating over ASCII strings or fixed-character formats in Go hot paths, prefer `for i := 0; i < len(str); i++` with a precomputed `[256]T` lookup table and branchless counter wrapping instead of `range` rune decoding, `switch` blocks, or `%` modulo arithmetic.
