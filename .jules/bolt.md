## 2026-08-02 - HTTP Client Reuse for Unix Domain Socket Connections
**Learning:** Instantiating a new `http.Client` and `http.Transport` on every request inside a hot-path use case (such as signature verification over Unix Domain Sockets) prevents connection reuse and connection pooling. This causes high connection-churn overhead, increases CPU latency, and raises memory usage with unnecessary heap allocations. Reusing a single pre-initialized, thread-safe `http.Client` and `http.Transport` across requests reduces CPU latency significantly (~2.8x speedup) and conserves substantial heap memory (~3.5x reduction in bytes allocated).
**Action:** Always store `http.Client` as a shared/reusable field in Go services instead of recreating it per-request, especially for high-frequency internal services (UDS or HTTP).
