## 2026-10-22 - Lock-free Atomic Counters & Direct String Concatenation in Rate Limiter Middleware
**Learning:** `RateLimiterMiddleware` runs on every incoming HTTP request path. Using `fmt.Sprintf` for key construction introduces reflection overhead (~194 ns/op, 48 B/op) and using `sync.Mutex` locks for counter increments causes CPU contention (~80.5 ns/op). Replacing key formatting with direct string concatenation (`strconv.FormatInt`) reduces execution time to ~127 ns/op, and converting `SafeCounter` to lock-free atomic operations (`atomic.AddInt64`) speeds up increments to 20.89 ns/op with 0 B/op heap allocation under high concurrency.
**Action:** On hot middleware and request handlers, prefer direct string concatenation / `strconv` over `fmt.Sprintf` and lock-free `sync/atomic` primitives over `sync.Mutex`.
