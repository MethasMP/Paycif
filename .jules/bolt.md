## 2026-07-23 - [WalletService Cache Key & Database Query Consolidation]
**Learning:** Manual string concatenation for simple string formats (like cache keys and descriptions) is ~3.15x to ~3.7x faster than `fmt.Sprintf` and avoids heap allocations. However, manual construction of complex JSON structures (e.g., payloads or metadata objects) is highly prone to syntax bugs (e.g., missing brackets). Therefore, it is best to keep standard JSON formatting (like `encoding/json` or `fmt.Sprintf`) for robust payloads while targeting simple keys and description patterns with string concatenation. Additionally, consolidating database transactions with SQL atomic statements (`INSERT ... ON CONFLICT DO NOTHING`) and checking `RowsAffected()` eliminates redundant database read round-trips (`SELECT EXISTS`) safely.
**Action:** Use string concatenation for basic cache keys and text formatting in hot paths; maintain standard serialization for JSON objects, and utilize `ON CONFLICT DO NOTHING` + `RowsAffected()` for atomic idempotency checks.
